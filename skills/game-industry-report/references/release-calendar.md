# 产品日历

## 召回范围

只从本地 `industry_news` 与 `release_calendar` 召回，禁止联网补充上线、测试或版本事件。必须反扫两个分区的全量输入，不能只扫描原始 calendar section：

- 事件分 3：新品测试、新品上线。
- 事件分 2：新品预下载、新品首次正式曝光、新品定档。
- 事件分 1：老品跨平台上线、老品重启回归、老品重大版本更新（如二次 OB、重大模式更新）。

“新品曝光”只认首次官宣、首曝、首次公开实机或正式立项公开；后续常规 PV、预约里程碑和重复宣传不召回。普通老品版本、资料片、赛季、联动、活动、皮肤、折扣、签到和常规运营不召回。

### 3839 相对时间

`haoyou_kuaibao_3839` 的时间轴是实时可变页面，历史日期卡片中的摘要可能包含按访问时刻生成或调整的“今天、今日、明天、明日、明早、后天”。这些词不得以时间轴卡片的 `event_at` 或目录日期为参照：卡片日期描述该卡所属事件日，不等于相对词的观察时刻。

本节规则只适用于 `source_key=haoyou_kuaibao_3839`，不得推广到新闻稿、推文或其他采集源。其他来源继续按原有来源发布时间、正文语境和报告窗口判断相对时间，不改变既有处理逻辑。

- 摘要包含相对时间但没有绝对日期时，采集器必须先读取同一详情页、同一更新时间的“更新动态”；其中存在明确月日时，以该更新动态原文为日期证据。
- 同日更新动态没有明确日期或读取失败时，以 Asia/Shanghai 的实际采集时刻 `observed_at` 为锚点解析；不得以卡片日期、报告日期或输出目录日期推算。
- 结构化记录必须同时保留原摘要、`observed_at`、`date_resolution_method`、详情页证据（如有）和 `resolved_event_text`。正文写绝对日期时，证据必须指向详情页绝对日期文本或解析后的结构化文本，不能只引用“明早”等相对词。

每一个召回信号都必须进入 `release_calendar_audit.json` 并在 `selection_decisions.json` 有 include/exclude；排除项同样留痕，不要求人工逐条重写自然语言，但不得静默丢弃。行业新闻维度覆盖自检不能替代本反扫。

## 次日及时性窗口

日报、周报、周末报的产品日历单独采用“正常报告窗口 + 次日”事件窗口。若正常采集窗口内的来源明确写出某产品将在窗口结束日次日上线、发售、发布、首次曝光、预下载或测试，该次日事件必须进入产品日历候选，与正常窗口内事件一起按多源门槛和优先级竞争。

- 日报 `date=D`：产品日历事件日期允许 `D..D+1`。
- 周报、周末报 `start..end`：产品日历事件日期允许 `start..end+1`。
- 月报不扩窗。
- 这只是产品日历的事件日期扩展，不扩展输入采集日期；来源仍必须来自正常报告窗口。行业新闻、AI 新闻、玩家舆论和深度观察继续严格使用原窗口。
- 次日事件必须由来源正文中的绝对日期直接支持。`haoyou_kuaibao_3839` 的相对时间必须先按上节规则解析并保留证据链；不能仅凭“明天、明早”等词推断。
- 多源门槛、独立来源去重、优先级公式和条数上限全部保持不变；次日事件不享受额外加分，也不保证入选。
- 审计节点必须写 `window_scope=next_day_lookahead`；普通窗口内节点写 `window_scope=report_window`。最终正文不显示这些内部字段。
- 为防止窗口重叠重复，同一“规范化产品名 + 事件日期 + 事件”若已通过次日窗口进入上一份已发布报告，下一份报告不得再次入选；若此前只进入候选或因上限被排除，则仍可在下一份报告重新竞争。该去重只适用于产品日历，不改变行业历史去重规则。

## 聚类与多源门槛

行业新闻与产品日历独立选材，不做两栏之间的互斥去重。同一产品/事件已进入行业新闻，仍须按本栏公式、时间与多源门槛竞争日历；行业新闻评分较低或被排除，也不降低其日历资格。不得使用“行业已收录/不跨栏重复”作为日历exclude理由。PC／主机产品不受行业主体评分结果牵连，日历事件/来源/公司分数公式不变。

这里取消的只是“行业新闻↔产品日历”的跨栏互斥；下述日历内部聚类、独立来源去重，以及上节的跨报告重复检查仍保留，也不改变行业与AI、行业与社区的去重。

按规范化产品名 + 事件日期聚类。同一产品同日的测试/上线及细分类别全部进入同一节点；来源标签差异写入 `observed_signal_types` 与 `observed_events`，不拆节点。

这里只对产品日历使用“产品名 + 日期”的特殊聚类。它不改变行业新闻的严格独立事件规则，也不得反向用于合并行业新闻。

同 URL 或同正文哈希的重复采集只计一个独立来源；不同来源的独立报道分别计数。正文入选必须 `appearance_count >= 2`；单源节点只能留在 selection decisions，不得进入正文。

规范化产品名时去掉“招募中、预约中、已开服、正版……品类说明”等采集标签，避免同一产品被拆成多个节点。

行业综合稿必须全文按句扫描，并按以下边界召回：

- 同一句出现唯一 `《产品名》`、当前事件和日期时，为该产品建立节点。
- 产品句与紧邻句组合时，事件句必须以“该作、本作、这款游戏、国际版、海外版”等明确回指主语承接；无主语短句、无法判断归属前一产品还是后一产品的句子不召回。
- 一篇文章可以为多个归属明确的产品分别建节点；同一句出现多个产品时，只召回能在逗号、顿号或分号分隔的局部短句中独立绑定“单一产品 + 事件 + 日期”的部分，其余不召回。
- “去年、此前、曾经、早在、过去、上线后、测试后”等历史语境不召回；扫描到“相关推荐、相关阅读、延伸阅读、猜你喜欢、更多推荐”后停止。
- “9月20日开启测试”“10月27日海外封测”等未来测试节点按新品定档召回；测试实际发生时仍按新品测试计分。
- 全文召回只扩大候选覆盖，不改变独立来源去重、多源门槛、优先级公式和日报/周末报4条、周报7条、月报12条上限。

## 优先级公式

事件类型因子：3/2/1，见召回范围。

来源强度因子：

- 出现次数 ≥3：3 分。
- 出现次数 =2：2 分。
- 出现次数 =1：1 分。
- 节点在 `industry_news` 出现过：在来源强度上额外 +1。

重点公司主体加分（名单版本`subject_genre_v2`，加分公式不变）：

- 与行业R3重点游戏主体完全共用[统一重点主体名单](focus-subjects.md)和`report-policy.json`；不把头部互联网主体或市场类别自动扩展为日历重点厂商。所有名单内厂商的新游节点按下述关系分级加分。
- 明确由重点公司或其内部工作室研发、发行、运营，或来源以“公司 + 产品”直接归属该产品时，加 3 分，审计标记 `company_relationship=direct`。
- 仅明确出现投资、参投、持股、战略投资、领投或跟投关系时，加 2 分，审计标记 `company_relationship=investment`；投资关系不得等同为自研、发行或运营。
- 公司主体及关系必须在产品局部句、标题中的产品直接归属，或结构化发行/开发字段中出现；关系不清或只是文章其他位置提及公司时不加分，不得凭产品常识补公司。
- 只对新品测试、上线、预下载、首次曝光和定档加分；老品跨平台、回归和重大更新不加。
- 加分不改变多源门槛，单源重点公司节点仍不得进入正文。

`基础分 = 事件类型因子 × 来源强度因子`

`优先级总分 = 基础分 + 重点公司主体加分`，范围 1–15。

总分相同时依次比较：重点公司关系加分更高、事件类型因子更高、独立来源更多、行业新闻有覆盖、原始首次出现顺序更早。即直属研发/发行/运营的 +3 节点在同分时优先于投资关系的 +2 节点。

日报/周末报最多 4 条，周报最多 7 条，月报最多 12 条；不设最低分、不凑数。只能从按上述顺序排列的多源候选前缀中选择，不能跳过高优先级候选改选更低项。

新品上线、测试、预下载与老品事件的实际发生日期必须位于产品日历事件窗口；日报、周报、周末报按上节允许到正常窗口结束日次日，月报仍等于正常报告窗口。更晚的节点保留审计但标记为不可发布。新品定档与首次曝光按报道发生窗口召回，允许其公布的未来日期晚于报告窗口；若来源明确描述的是次日实际曝光节点，则标记为 `next_day_lookahead`。排序时先放可发布节点，再按优先级总分排序。

生成其他分区的 `selection_decisions.json` 后，运行 `<workspace>/scripts/sync_release_decisions.py --audit <release_calendar_audit.json> --decisions <selection_decisions.json> --max-items <4|7|12>` 确定性写入全部产品日历 include/exclude 与分数。

## 正文格式

每项一个 bullet：

```markdown
- {厂商}开发/发行的{品类}{手游|端游|主机游戏|多平台产品}《{游戏名}》于{日期}在{平台}{事件}；{一句读者向说明}。
```

分号前至少有品类、型态、游戏名、事件；厂商、日期、平台仅在原文有证据时写。缺失时降级，禁止猜测。分号后不写多源、评分或筛选过程。

示例：

- 合格：`- 星辉游戏发行的策略卡牌手游《示例游戏》于 7 月 22 日在 Android、iOS 开启公测；主打多人协作与赛季制。`
- 不合格：`- 国内多款手游于本周上线，包括《A》《B》《C》。`（合并多个产品）
- 不合格：`- 《示例游戏》获得三个日历源与行业新闻共同验证。`（把审计过程写入正文）

正文只描述产品事件与读者向意义。跨源重复、行业新闻重合、出现次数及优先级只能存在于 `_intermediate`、结构化审计或结果摘要。
