# 深度观察

## 正文

日报和周末报默认选 1–2 条。周报只消费 `output/deep_observation_review/<周报start>_to_<周报end>_selection.md` 中用户明确选择的条目，无 selection 时允许省略。selection 文件名表示“交给哪一期周报消费”，不表示候选数据窗口。

每条使用“观察 / 分析”两层：观察提出变化与核心问题；分析至少两个段落，展开机制、成立前提、前提如何松动及下游影响。事实和数字必须有 source 原文证据。

- 观察用一段提出变化和核心问题，不写业务命令或口号。
- 分析用两到三段展开“变化—机制—下游影响”，把为什么值得跟踪写进分析，不另设空泛“影响/启示”段。
- 数据和案例只用于锚定问题，不能用公司名单、新闻罗列或财务数字挤占机制解释。
- 若主题讨论某种模式为何失灵，必须说明该模式原先成立的前提、前提如何松动及其连锁反应。
- 核心输入必须来自本期已入选事件；综合主题至少有两个能共同支持结论的原始来源。单篇高质量 newsletter 可支撑单一分析，但不得把作者判断冒充原始事实。
- 与上一期深度观察撞题时，只有窗口内出现实质新证据、新机制或新阶段才可继续；否则换题，避免重复观点换案例。

## 独立卡片压缩文案

最终 Markdown 继续使用“观察 / 分析”长文结构；不要为了卡片缩短正文。每条深度 item 在 `report_items.json` 另写 `card_copy`，供 `scripts/feishu_common.py` 渲染：

```json
{
  "card_copy": {
    "source_label": "媒体或作者 + 内容类型，如 NAAVIK文章",
    "summary": "一句话概括变化、机制与核心结论。",
    "insights": [
      {"title": "短标题", "detail": "一句解释。"},
      {"title": "短标题", "detail": "一句解释。"},
      {"title": "短标题", "detail": "一句解释。"}
    ]
  }
}
```

- `source_label` 必须根据该 item 的真实来源填写，采用“媒体/作者 + 内容类型”，例如 `NAAVIK文章`、`公司访谈`；不要带冒号，脚本统一渲染为“来源标签：原标题”。
- `summary` 只写一行、一个完整结论，建议 40–70 字，最多 100 字；不要复述标题，不要使用“观察 / 分析”标签。
- `insights` 必须为 3–6 条。按真实存在的独立机制决定数量，不固定为 5 条或 6 条，不机械拆句凑数。
- 每条使用“结论型短标题 + 一句解释”：标题建议 6–18 字、最多 30 字；解释最多 160 字，只承担一个机制、前提、影响或边界。
- 优先覆盖“变化是什么、为什么成立、价值如何产生、商业闭环如何形成、边界或风险在哪里”；不要求每条都覆盖全部维度。
- 卡片文案只能压缩、重组正文中已有结论与来源支持的事实，不得新增案例、数字、主体或推断。关键数字只保留能支撑洞察的部分。
- 不把公司名单、数据罗列或近义句包装成多个洞察；加粗标题单独浏览时应能还原整张卡片的逻辑链。

## R/I/E/C

本节R/I/E/C为深度观察的独立模型，不是行业E×R+M；四维各0–3、原资格线不变。主体名称统一查`focus-subjects.md`，行业的5分线与M0/1不套用到深度观察：

- R 相关性：国内/中国移动/[统一重点主体名单](focus-subjects.md)/重点品类为 3；有明确迁移点为 2；弱迁移为 1；无关为 0。
- I 结构性洞察：完整“变化—机制—下游影响”为 3；缺一环为 2；主要是现象为 1；无结论为 0。
- E 证据强度：完整可核验证据链为 3；可靠但偏薄为 2；主要是观点或有限摘录为 1；不可核验为 0。单篇高质量分析可以为 3；综合主题至少需要两个共同支持结论的原始来源。
- C 卡片吸引力：问题清晰且可迁移为 3；值得讨论但需背景为 2；只有话题性为 1；没有可用讨论点为 0。

重点主体或优先赛道只能提高 R，不能代替 I/E/C。数据很多、主体重要、赛道热门都不是结构性洞察或卡片吸引力的自动加分理由。

候选全集基础资格：I>0、E>0、有真实 URL、事实受来源直接支持。周报正文自动资格为总分 ≥9；用户指定卡片是唯一例外，低于 9 也随正文写入并在 JSON 标 `card_designated: true`。

## 周四候选质量门禁

基础资格只是必要条件，不足以进入发给用户的周四候选文件。每条候选还必须依次通过以下门禁；未通过者留在审计记录中并说明排除原因，不得因 I>0、E>0 就展示。

### 来源顺序与准入

1. 先完整检查候选窗口内用户已配置为 `deep_analysis` 的 newsletter 更新；这些来源是第一优先级，不得被普通行业新闻挤掉。
2. 再检查窗口内已成稿的日报/周末报深度内容，但仍须重新执行本节门禁，已成稿不等于自动成为周四候选。
3. 仍有独立高价值主题时，再从窗口内已采集材料反扫深度市场研究、横向比较、开发复盘和含内部数据的访谈。普通快讯、公告、发布稿、短摘要和单一现象稿只能补充事实，不能单独支撑候选。

候选的核心来源至少满足以下一条质量路径：

- **深度分析**：有完整问题、机制、成立前提和影响链，不只是作者结论或趋势判断。
- **横向比较**：在同一维度比较至少两个项目、公司或产品，并能得出共同机制或关键差异。
- **数据型案例**：提供足以改变判断的内部数据、市场数据、具体决策或开发过程；至少有三个互不重复的实质证据锚点，其中至少一个是数据、明确决策、流程变化或可核验对比。

“有趣事实”必须帮助解释机制、反常识结果或决策约束；趣闻、名单、单个数字和宣传性说法不单独构成深度。厂商自述可作为事实来源，但若没有方法、口径或第三方交叉证据，不得仅凭宣传性主张给 E3。付费墙预告、正文过短的摘要和无法读取全文的页面不能作为唯一核心来源。

### 主题级合并

- 先为材料写 `topic_key = 主体/产品 + 核心问题 + 关键机制`，再生成候选。`topic_key` 相同或只是同一问题的不同事实切面时必须合并。
- 同一篇文章或同一组高度重合来源默认最多形成一个候选；把其中的数据、案例、机制和边界捏合为一个完整选题，不得按段落、事实点、产品名或卡片洞察拆成多个候选。
- 只有当两个角度回答不同决策问题、使用基本不重合的证据集、拥有不同下游影响，且各自独立通过来源准入与 R/I/E/C 评分时才能拆分；必须在审计中写明 `split_justification`。写不出清楚理由就合并。
- 不设候选数量目标。“不截断”只表示保留全部通过门禁的独立候选，不表示要扩充数量；宁可少，不得拆题、降分或用普通新闻凑数。

### 表达与首读测试

- 标题直接写清“谁/什么发生了什么变化，以及关键结果或机制”，优先使用事实动词和具体名词。读者只看标题和一句话观察，就应知道主题、变化与核心结论。
- 禁止用抽象概念替代结论，避免无必要的“范式、重构、飞轮、解法、信号、想象空间、方法论”等词；确需使用时必须紧接具体含义。不要用隐喻、对仗、反问或层层定语制造深度感。
- 一句话观察只承担一个核心判断，最多 100 字；分析要点只保留互不重复的机制、证据和边界，不重复改写标题，不为了显得完整而过度解释。
- 写完后执行首读测试：若无法用一句日常、专业中文向同事解释“这条到底要说什么”，必须重写；重写后仍不清楚则排除。C3 只给无需额外背景即可理解、且讨论点明确的候选。

### 发送前审计

周四审计产物须为每个展示候选记录 `topic_key`、`source_priority`、`quality_route`、至少三个 `evidence_anchors`、`merge_basis`，拆分时另写 `split_justification`。发送前逐项确认：

1. 没有重复 `topic_key`；同一核心来源没有无理由对应多个候选。
2. 每条都通过至少一条来源质量路径，普通新闻只作为辅助来源。
3. 标题与一句话观察通过首读测试；R/I/E/C 未因主体热门、数字多或来源多而虚高。
4. 候选数量由质量门禁自然产生，没有人为凑数；卡片洞察来自同一完整选题，不反向制造新候选。

## 周四选择与卡片交接

周四展示“上周四至本周三”七天窗口内全部合格候选，不截断；分数只用于排序。候选数据窗口固定截至周三，不能为匹配周五周报而后移。用户从正文合格候选中选择条目，并从候选全集唯一指定一条卡片。

自目标周报结束日 2026-09-24 起，周四候选只通过独立“飞书周四备选 Bot”发送和接收选择，不再依赖 Codex 任务对话等待用户。候选生成后必须先写 `output/deep_observation_review/<目标周报ID>_candidates.md`，再运行 `python scripts/feishu_deep_review.py send --weekly-id <目标周报ID>`；发送失败或 Bot 未绑定必须明确失败，不得把“已生成候选”表述成“已送达”。

用户飞书回复由长连接监听器立即写到 `data/feishu/deep_review/replies/<receipt_id>.json`。周五任务先运行 `python scripts/feishu_deep_review.py status --weekly-id <目标周报ID> --json`：若存在有效回执且 selection 尚不存在，按 `raw_reply`、候选文件和回执 ID 顺序整理 selection；融合多个候选时，第一个卡片 ID 是主卡并必须进入正文，其余 ID 只作为整合参考。selection 另须写 `选择来源`、`飞书回执ID`、`正文候选ID`、`指定卡片候选ID` 与可选的 `卡片整合参考ID`，并通过 `python scripts/deep_observation_handoff.py lint-selection --selection <path>`。若没有目标周报回执，周报不得自动代选，但可以省略第五栏继续生成；若已有有效回执但整理或校验失败，不得静默省略，交给兜底任务重试并明确报错。

候选展示必须逐条包含标题、R/I/E/C 与总分、一句话观察、分析要点、真实 http(s) 来源 URL，以及“来源标签：原标题 + 一句话总结 + 核心洞察”的卡片正文预览。E=0、I=0 或无可核验 URL 的候选不展示。

双窗口交接固定如下：

- 候选数据窗口：周四运行日减 7 天至减 1 天，即上周四至本周三。
- 目标周报窗口：周四运行日减 6 天至当天，即上周五至本周四。
- 运行 `python scripts/deep_observation_handoff.py windows --thursday <YYYY-MM-DD>` 取得两个窗口；不得手算后混用。
- 用户选择文件固定按目标周报窗口命名：`output/deep_observation_review/<目标周报start>_to_<目标周报end>_selection.md`。
- 文件开头同时写 `- 候选数据窗口: <候选start>_to_<候选end>` 和 `- 目标周报窗口: <周报start>_to_<周报end>`。

每条一个 `### N. 标题`，后接“观察：”“分析：”和 `- 来源:媒体,《标题》,http(s)://...`；全篇有且仅有一个标题带 `★卡片:`。周五按自身周报 ID 精确消费这份选择，不得因内部候选窗口早一天而拒绝，也不得替用户自动增删或换卡。若目标 ID 文件缺失但以候选数据窗口命名的旧 selection 存在，必须判定为交接错误并停止；不得把它当成“用户未选择”后静默省略第五栏。

周五去掉 selection 标题中的 `★卡片:`，把所有人工选择写入第五栏，并把唯一指定项的最终正文标题写入周报目录 `deep_card_choice.txt`。随后运行 `report_artifacts.py validate --require-artifacts`；该校验必须确认目标 ID selection、第五栏标题与 `deep_card_choice.txt` 闭环一致。每周最多推一张，只推指定项；不按正文顺序自动选，不降级。卡片视觉、按钮和压缩格式由 `scripts/feishu_common.py` 负责，不在本技能重复定义。

周报抽取时若目标 ID selection 存在，必须向 `extract_report_inputs.py` 传 `--deep-selection`。抽取器会把候选窗口中位于周报常规窗口之外、但已被选择条目引用的来源补为 `deep_analysis` 输入，并标记 `deep_selection_supplement: true`；这些补充记录只服务深度观察，不得进入行业新闻、AI、社区或产品日历。
